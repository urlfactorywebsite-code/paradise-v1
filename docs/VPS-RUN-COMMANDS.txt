3. ONE-TIME FIX FOR THE UNTRACKED COMPOSE FILE

Run only if git pull reports that untracked compose.npm.yaml would be overwritten.
This moves the manually created file into a private backup directory. It leaves
an already tracked file alone. The current repository supplies this configuration.

(
  set -e
  cd /opt/paradise-v1
  if [ -f compose.npm.yaml ] && ! git ls-files --error-unmatch compose.npm.yaml >/dev/null 2>&1; then
    config_backup=$(mktemp -d /root/paradise-config-XXXXXX)
    mv -- compose.npm.yaml "$config_backup/compose.npm.yaml"
    echo "Previous configuration saved in: $config_backup"
  fi
  git pull --ff-only
)

5. START, STOP OR RESTART

Run from /opt/paradise-v1. Pick one operation.

Start existing containers without rebuilding:
docker compose -f compose.yaml -f compose.npm.yaml up -d --wait

Restart only the app using its existing configuration/image:
docker compose -f compose.yaml -f compose.npm.yaml restart app

Apply configuration changes to the app without rebuilding or recreating the DB:
docker compose -f compose.yaml -f compose.npm.yaml up -d --no-deps --wait app

Stop the app and database, preserving containers and data:
docker compose -f compose.yaml -f compose.npm.yaml stop

Restart does not apply changed environment variables. Use up for those changes.
Do not run down -v: it deletes the project's database and backup volumes.

7. DATABASE BACKUP AND COPY OUT

cd /opt/paradise-v1
docker compose -f compose.yaml -f compose.npm.yaml exec -T app npm run backup
docker compose -f compose.yaml -f compose.npm.yaml exec -T app ls -lh /app/data/backups

Replace REPLACE_WITH_ACTUAL_FILENAME.dump with the filename printed by backup:
install -d -m 700 /root/paradise-backups
docker compose -f compose.yaml -f compose.npm.yaml cp app:/app/data/backups/REPLACE_WITH_ACTUAL_FILENAME.dump /root/paradise-backups/
chmod 600 /root/paradise-backups/*.dump

Keep an off-server copy of important backups. Dumps contain private account and
business data. The backup volume is persistent, but is on the same VPS.

The container message '.env not found. Continuing without it.' is expected:
Compose injects database environment variables without mounting the host .env.
Check the command exit status and 'Backup saved' message for the backup result.

8. ADMINISTRATOR PASSWORD RECOVERY (ONLY WHEN NEEDED)

Replace EXISTING_ADMIN_USERNAME with the existing administrator username.
The tool prompts for a hidden 12-128 character password, makes a database backup,
reactivates that administrator and revokes their existing sessions.

cd /opt/paradise-v1
docker compose -f compose.yaml -f compose.npm.yaml exec app npm run recover-admin -- EXISTING_ADMIN_USERNAME

9. DATABASE RESTORE INTO A NEW DATABASE (ONLY WHEN NEEDED)

Replace the backup filename and choose an unused lowercase database name.
This restores a separate database; it does not overwrite or switch the live one.

cd /opt/paradise-v1
docker compose -f compose.yaml -f compose.npm.yaml exec -T app npm run backup
docker compose -f compose.yaml -f compose.npm.yaml exec -T app npm run restore -- /app/data/backups/REPLACE_WITH_ACTUAL_FILENAME.dump paradise_restored_20261109

After restore succeeds, validate it before changing the app's target database.
For an intentional cutover, preserve .env privately, edit POSTGRES_DB to the
restored name, then recreate the services with both Compose files. Keep the
previous database. Changing POSTGRES_DB alone does not copy or restore data.

11. FRESH INSTALL ONLY

Skip this section on the existing installation. It is for a new server/path.
First verify Docker, Compose v2, Git, the proxy network and free host port 6400.
