# API contract

The authenticated OpenAPI 3.1 reference at `/api.html` and `/api/openapi.json` enumerates routes and schemas. The API operates on one company workspace.

## Authentication and permissions

`GET /api/auth/status` returns `{initialized,user,csrfToken}`. First-run `POST /api/auth/setup` accepts `{name,username,password,demo}`. Login accepts `{username,password}` at `/api/auth/login`; preserve the returned cookie and CSRF token. Authenticated writes require `X-CSRF-Token` and JSON content type when sending a body.

`GET /api/auth/me` reads the account. `POST /api/auth/password` accepts `{currentPassword,password}` and returns a replacement session after revoking old sessions. `POST /api/auth/logout` invalidates the current session. `/api/auth/sessions` supports GET (list owned sessions) and DELETE (revoke other sessions); DELETE `/api/auth/sessions/{id}` revokes one other owned session.

Catalog, settings, internal approval, team, audit, data export, backup and expiry administration require Administrator. Customer and quotation workflows are available to Employees, subject to deletion/approval rules.

## Resource convention

`/api/customers`, `/api/categories`, `/api/products`, `/api/quotations` provide:

- GET collection → `{data,pagination:{page,pageSize,total,totalPages}}`.
- POST collection with `{data:{...record}}` → 201 `{data,version,updatedAt,revision}`. IDs can be generated by the server.
- GET `/{id}` → `{data,version,updatedAt}`.
- PATCH `/{id}` with `{data:{...changes},version}`.
- PUT `/{id}` with `{data:{...completeRecord},version}`.
- DELETE `/{id}` with `{version}` → `{ok:true,revision}`.

These record updates/deletes also accept `If-Match: "3"` instead of a body version. Missing versions return 428; stale versions return 409. Customer duplicate matches return 409; an explicitly reviewed duplicate can use top-level `allowDuplicate:true`. Referenced customers/categories cannot be deleted. Removing products does not remove saved quote snapshots.

Search parameters: `q`, `page`, `pageSize` (default 25, maximum 100), `sort`, `direction`. Customers/categories/products sort by `name` or `updated_at`; quotations support `date`, `number`, `total`, `status`, `updated_at`. Products support `category`, `active=0|1`; categories support `active`. Quotations support `status`, `customer`, `salesperson`, `from`, `to`, `min`, `max`. Amount filters use INR. Sort columns are allow-listed; SQL values are bound parameters.

`GET /api/customers/{id}/quotations` provides customer quotation history. `GET /api/catalog` returns categories/products.

## Pricing and quotations

`POST /api/pricing/calculate` accepts `{productId,cfg}`. Numeric quantity/size/dimension fields must be JSON numbers; selected values must match the product's options. Catalog rates and extra charges use decimal INR; calculated totals use integer paise.

Create a quote using `{data:{cid,date,valid,items:[{pid,cfg,notes}],disc:{t:"p",v:5},del:0,oth:0}}`. Select all required product options in `cfg`. New quotes start as Draft. Submitted item totals, numbering, creator, snapshots and history are not trusted; the server calculates/assigns them.

| Endpoint | Contract |
| --- | --- |
| POST `/api/quotations/preview` | Quotation object; validate/recalculate without saving or consuming a number |
| POST `/api/quotations/{id}/status` | `{version,status}`; records history, enforces administrator internal approval |
| GET `/api/quotations/{id}/history` | Server status history |
| POST `/api/quotations/{id}/duplicate` | `{version}`; preserves snapshots, creates Draft/new number |
| POST `/api/quotations/{id}/reprice` | `{version}`; explicitly applies current active catalog prices |
| GET `/api/quotations/{id}/pdf` | Server PDF attachment; no status change |
| POST `/api/quotations/expire` | Administrator `{asOf,revision?}`; expire overdue pending/internal-approved/sent records |

Ordinary resource PUT/PATCH preserves the current quotation status; use the explicit status endpoint. Drafts and customer-approved/rejected/cancelled quotations are not changed by expiry processing.

## Settings, reports and atomic changes

`GET /api/settings` returns `{data,version}`; administrator PUT/PATCH accepts `{data,version}`.

`GET /api/dashboard`, `/api/reports/summary`, `/api/reports/quotations.csv` use quotation filters. Report totals are quoted values, not revenue. CSV text cells that might trigger formulas are escaped.

`GET /api/state` bootstraps the current UI with `{state,revision,user}`. `POST /api/changes` accepts `{revision,changes:[{collection,action,id,record}]}`. Collections: `cats`, `products`, `customers`, `quotes`, `set`; actions: `upsert`, `delete`. Upserts provide the complete changed record; deletes provide its ID. Settings cannot be deleted. Up to 200 changes commit atomically or all roll back. The client cannot write audit history. Compatibility `PUT /api/state` accepts `{state,revision}` and uses the same validation/storage.

## Team, audit and recovery

- GET/POST `/api/users`: administrator list/create; creation takes `{name,username,password,role}`.
- GET/PATCH/DELETE `/api/users/{id}`: edits take `{version,name?,username?,role?,active?}`; removal takes `{version}`. The last active administrator is protected.
- POST `/api/users/{id}/reset-password`: `{version,password}`; revokes sessions and requires password replacement. Use normal Change password for your own account.
- GET `/api/audit`: administrator pagination, optionally `entityType`, `entityId`, `actorId`. No audit mutation endpoint exists.
- GET `/api/data/export`: business JSON without credentials/sessions.
- GET/POST `/api/backups`: list/create consistent database backups.
- GET `/api/backups/{name}`: authenticated administrator download scoped to the configured backup directory.

Restore and offline administrator recovery use the local commands in the README. They are not unauthenticated HTTP endpoints.

## Errors

Errors return `{error,requestId}`. Codes: 401 unauthenticated, 403 forbidden, 404 missing, 409 stale/conflicting, 413 oversized, 422 invalid, 428 version required, 429 throttled. After conflicts or uncertain network outcomes, fetch current data and review the preserved draft before explicitly retrying.


## PostgreSQL storage (v3)

The API contract is unchanged. Health/readiness now report `database: "postgresql"` and `schemaVersion: 3`. Administrator database backups use PostgreSQL custom-format `.dump` files and `application/octet-stream`. Restore requires a new PostgreSQL database name; run it with the Docker commands in the README. SQLite import is an offline command into an empty PostgreSQL workspace.
